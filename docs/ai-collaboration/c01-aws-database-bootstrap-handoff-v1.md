# PART D — MIGRATION BOOTSTRAP PLAN

## 24. Migration mechanism

Backend package scripts expose:

```text
npm run db:migrate:deploy
→ prisma migrate deploy
```

This is the expected non-interactive production migration mechanism.

Production SST explicitly disables migrations on application startup.

No production migration is authorized by this handoff.

---

## 25. Fresh database migration expectation

For a positively identified fresh database, accepted C-01 repository state expects:

```text
0 → 70 migrations
```

The I7 acceptance suite replayed all 70 migrations successfully in disposable PostgreSQL environments.

Before real execution:

1. pin exact production application commit;
2. confirm production DB is the intended fresh target;
3. take snapshot/backup if a database resource already exists and release authority requires it;
4. confirm database connectivity from the authorized migration execution environment;
5. run `prisma migrate status` read-only first;
6. verify expected 70 migration directories in the exact deployment artifact;
7. obtain explicit production-bootstrap/migration authorization;
8. only then run `prisma migrate deploy`.

Do not use:

- `prisma migrate dev`;
- `prisma db push`;
- manual copy/paste of individual migration SQL;
- startup auto-migrations.

---
