* **Default State:** A circular primary-colored FAB floating at the bottom-right of the screen (above the sticky footer navigation).  
* **Active/Thinking State:** When a background task is running (e.g., AI is drafting a contract), the FAB transforms into a pulsing pill: \[ 🤖 Drafting Pitch... \].

### **B. The Bottom-Sheet Modal (Minimize/Maximize)**

When the creator taps the FAB, the chat does *not* open a new page. It opens as a **Bottom-Sheet Modal**.

* **Expanded State:** The sheet slides up, taking up **80% of the screen height**. The top 20% of the screen is dimmed but still visible, reminding the creator of what they were looking at (e.g., a specific brand deal).  
* **The Multitasking Swipe (Minimizing):** If the creator needs to check a metric on the screen behind the chat, they swipe the modal down. It snaps back into the FAB.  
* **State Preservation:** The frontend state manager (e.g., Zustand, Redux, or React Context) *must* keep the chat array mounted in memory. When the FAB is tapped again, the chat opens instantly exactly where they left off. No reloading.

## **🧠 2\. CONTEXT-AWARE ROUTING ENGINE**

For the AI to know *where* the creator is, the frontend must inject a **Context Payload** invisibly every time a user opens the chat or sends a message.

### **The Frontend Injection Payload**

When the user sends a message (or taps a suggested prompt), the frontend API call includes the current screen state:  
JSON  
{  
  "user\_prompt": "Is this a good deal?",  
  "current\_context": {  
    "active\_tab": "/collaborations/active",  
    "viewing\_entity": "deal\_id\_9482",  
    "entity\_data": {  
      "brand\_name": "Sephora US",  
      "offered\_rate": 1500,  
      "deliverables": "1 Reel, 2 Stories",  
      "creator\_average\_rate": 1250  
    }  
  }  
}

### **Contextual First-Message Overrides**

Because the AI knows where the user is, the default greeting changes dynamically when they tap the FAB:

* **If on Home Screen:** *"Good morning\! Need help analyzing your daily briefing?"*  
* **If on Deals (Viewing Sephora):** *"I see you're reviewing the Sephora deal. Based on your average rate ($1,250), their $1,500 offer is strong. Want me to draft an acceptance message?"*  
* **If on Content Pulse (Viewing a Reel):** *"This Reel has a 4.2x velocity. Want me to generate a pitch template to send to brands based on this performance?"*

## **⚡ 3\. ACTION EXECUTION ENGINE (Generative UI)**

The Assistant cannot just output raw text. It needs to return **Action Hooks** so the frontend can render native UI buttons right inside the chat stream.

### **The AI Response Schema (Tool Calling)**

Instead of returning a plain string, the LLM (Gemini) is instructed to output a structured JSON object containing a reply\_text and an optional action\_ui array.  
**Example Backend Response to Frontend:**  
JSON  
{  
  "reply\_text": "I've drafted a polite counter-offer asking for $1,800 due to the quick turnaround time requested by Sephora.",  
  "action\_ui": \[  
    {  
      "type": "BUTTON\_PRIMARY",  
      "label": "Send Counter-Offer to Sephora",  
      "action\_trigger": "UPDATE\_DEAL\_STATE",  
      "payload": {  
        "deal\_id": "deal\_id\_9482",  
        "new\_status": "COUNTERED",  
        "proposed\_value": 1800  
      }  
    },  
    {  
      "type": "BUTTON\_SECONDARY",  
      "label": "Edit Text",  
      "action\_trigger": "OPEN\_TEXT\_EDITOR",  
      "payload": null  
    }  
  \]  
}

### **How it Looks on the UI:**

1. The AI's text bubble appears.  
2. Directly below the text bubble, a native, tappable UI button renders: \[ Send Counter-Offer to Sephora \].  
3. When the creator taps it, the frontend executes the UPDATE\_DEAL\_STATE function, moving the Sephora deal to the next Kanban stage in the background, and the AI replies: *"Counter-offer sent\! I'll track their response in your deals pipeline."*
